  1. 01 Maritime · Featured

    Helm.Warning — Maritime Safety Information Pipeline

    A maritime safety platform for collecting, parsing, validating, and visualizing navigational warnings — built to turn complex warning text into structured, map-ready information.

    Read the full case study
    The problem
    Navigational warnings arrive as plain radio text. Plotting hazards onto a voyage means reading coordinates by hand and updating charts manually — slow, and easy to miss on watch.
    Constraints
    Every warning must stay traceable to its source text, ambiguous coordinates can never be silently guessed, history must be preserved when a source stops listing it, and the result has to stay usable at sea.
    The solution
    Scheduled Python scrapers harvest warnings from official NAVAREA coordinators. A deterministic parser extracts coordinates, geometry, and validity dates; parsed records are validated and stored in Supabase (PostgreSQL + PostGIS) and plotted on an interactive Leaflet map. An admin-gated React console handles review, editing, and audit.
    Architecture
    Official sources → scheduled scrapers (GitHub Actions) → rule-based parser with fail-closed AI fallback → validation → Supabase (PostGIS) → public map (vanilla JS) + admin console (React + Supabase Auth).
    Parsing
    Extraction is deterministic and rule-based, with AI used only as a controlled fallback that fails closed. Coordinates are validated against the source text; anything ambiguous is flagged for review rather than guessed, and every parsed record carries an explicit confidence classification.
    Data integrity
    The original raw source text is stored unmodified, ingestion is upsert-only so history is never silently lost, and every manual edit through the admin console writes an audit record.

    Maritime · Geospatial · TypeScript · Python · Supabase

  2. 02 Maritime

    Helm.Ports — World Maritime Ports Explorer

    A fast, self-contained explorer for 5,410 world ports and anchorages — channel depths, tidal ranges, and entrance restrictions screened in milliseconds, with no database and no map tiles.

    Read the case study
    The problem
    The world's port data exists — the NGA World Port Index — but it lives in static PDFs and heavyweight GIS portals. The questions that actually matter on passage (can this vessel enter? how deep is the channel? is the entrance tide-restricted?) shouldn't require accounts, tile servers, or bandwidth.
    The solution
    A full-stack explorer over the complete 5,410-record NGA Publication 150 dataset (2019 edition). Search, faceted filters — country, port size, vessel size, minimum channel depth, tidal-range window, entrance restrictions — and sorting all run against the dataset held in memory: queries answer in 1–3.5 ms, with no database at all.
    The map
    A custom SVG world map with level-of-detail: roughly 160 major hubs visible at 1× zoom, all 5,410 points at 8× and above, with viewport culling on every pan and zoom. Coastlines come from Natural Earth data served locally — zero tile services, zero API keys, fully offline-capable cartography.
    Data honesty
    Soundings are single recorded observations from the 2019 edition, and the app says so — it presents itself as a planning and reference tool, never as a real-time navigation source.

    Maritime · Geospatial · React · TypeScript · Express · Tailwind CSS

  5. 05 Operations

    Bond Vault

    An inventory system for tracking, auditing, and managing bond stock — designed around the logs officers already keep.

    Read the case study
    The problem
    The slop chest — a vessel's bond store — traditionally runs on paper: crew tabs, stock counts, and audits are reconciled by hand, and discrepancies surface late.
    The solution
    A purpose-built ledger that tracks opening stock, received, and issued provisions, computes theoretical remaining-on-board per item, logs physical counts as discrepancy audits, and keeps a running tab per crew member — with print-ready statements and signature lines for sign-off.
    Offline & audit
    Offline-first by design: data persists to IndexedDB through automatic save cycles, exports to CSV, and mirrors to a human-readable JSON state file that can restore the whole app. Multi-currency support and a low-light dark theme sized for night bridges.

    TypeScript · React · IndexedDB

  7. 07 Tools

    Mudhra Converter

    A converter between modern Malayalam Unicode and the legacy ML-TT ASCII typefaces still used in print — chillu normalization, longest-match conjunct sequencing, and pre-base vowel reordering.

    Read the case study
    The problem
    Malayalam for the web is written in Unicode, logically mapped — you type how it sounds. The legacy ML-TT typefaces still used across print and DTP are visually mapped ASCII, where you type how it looks. Between the two sit hundreds of conjunct characters, pre-base vowels, and invisible joiners.
    The solution
    A converter built as a small parsing engine: it strips zero-width joiners, normalizes chillu characters, matches the longest possible conjunct sequences first, reorders pre-base vowel signs to their visual position, and splits two-part vowels around the base consonant.
    Why it matters
    One paste turns a Unicode document into copy for the print shop — and all conversion runs client-side: nothing is uploaded or stored.

    JavaScript · Vite · Client-side

About

Two crafts, one standard of attention

As a Third Officer on ocean-going tankers, the work is watchkeeping, passage planning, bridge equipment, and safety management. Months at sea under constrained satellite connectivity made it obvious how much operational work still depends on paper logs, fragmented schedules, and tools that assume a stable network.

I learned full-stack development the same way I learned the bridge: by needing it. I build with AI coding assistants in the loop, and I am deliberate about how they are used: the requirements, the design decisions, the review, and the responsibility for what ships are mine, while the drafting and refactoring accelerate the work. Every application I publish starts from a real bottleneck on board, turning repetitive manual records into software that still works when the link drops.

The through-line is not “maritime themed apps.” It is procedural care. A watch and a codebase both fail the same way: quietly, then all at once, if the details are treated as optional.
